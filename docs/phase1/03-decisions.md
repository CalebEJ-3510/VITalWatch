# Phase 1 — Decisions (route model, demo clock, tokens, type, assets)

One page per decision: what was chosen, why, and what would make us revisit.

## D1 — Route model convention

**Chosen: keep the current flat route names; evolve toward the §4.1 model without an
`/app/` prefix.**

- Phase 1 changes no route paths (only additions: `POST /api/pv/code`).
- Phase 2 makes `/` the public landing page. Authenticated requests for `/` resolve to
  the role-aware Operations Home (redirect, not marketing inside the workspace).
- Phase 3 adds the Operations Home (candidate: `/home`, with `/` redirecting to it when
  authenticated). `/login?next=` default resolves to that workspace, not to `/`.
- Phase 4/5 introduce `/study/{id}` subview structure and signal/case workspaces under
  existing names (`/ae`, `/signals`, `/investigation/{id}`) — no breaking redirects.
- The `/app/...` prefixed alternative (§4.1) was **rejected for this codebase**: every
  existing route, deep link, README row and API consumer would need a redirect shim for
  zero authorization gain — the middleware already gates everything, and the prefix
  would be decoration pretending to be a boundary (§15 anti-pattern: hiding vs.
  enforcing).

## D2 — Demo clock and data snapshot

**Chosen: fixed dataset snapshot + live server clock for all deadline/freshness
semantics. No frozen "demo time".**

- The dataset is anchored: `app/datagen.py` sets `TODAY = date(2026, 8, 22)` and the
  fixed seed (`SEED_RANDOM_SEED=20260822`) regenerates the identical portfolio and
  audit head on every rebuild.
- Clocks run on `utcnow()` at request time (`pv.clock_counts`, `roles.safety(now=…)`).
  This is deliberate: a statutory-deadline indicator must be *true at view time*, and
  the safety lens already derives clock state on read rather than trusting the
  intake-time snapshot (`roles.py:236-244`).
- Consequence for UI: every deadline/freshness display must show its as-of instant
  (the `freshness` / `deadline_clock` macros enforce this). "As of page load" is the
  correct label — never implied real-time.
- Rejected alternative: a fully frozen demo clock (`DEMO_NOW`) would make deadline
  demos deterministic but would teach the UI to display a lie; the brief's state rules
  (§10.1, §13.2) require real clock semantics everywhere.

## D3 — The indigo question (resolved in writing, permanently)

Resolved in `app/static/tokens.css` header — summary:

- `--reference` (indigo) = *the line you are measured against, and where you stand
  relative to it* — reference marks, thresholds, deadline ticks, and active-context
  markers (active nav, selected row). Never a data state, never decoration.
- Primary **action** = ink (`--action`), not indigo.
- **Focus** = 2px outline in `--focus`/`--focus-on-dark`, not indigo — an interaction
  state, not a position against a line.
- States: breach / review / within keep their meanings; **unknown** (dotted) and
  **stale** (dashed + as-of time) added because §10.1 requires them. Urgency is filled,
  status is tinted; color never carries meaning alone.

## D4 — Typography system (licensed, self-hosted)

| Role | Face | License | Delivery |
|---|---|---|---|
| Display (landing only, never tables/forms) | Fraunces variable (opsz/wght/SOFT/WONK) | OFL | `fraunces-latin-var.woff2`, `font-display: optional`, never preloaded |
| Body/UI | Manrope variable | OFL | `manrope-latin-var.woff2`, `font-display: swap`, **only** regular preloaded |
| Identifiers/mono | IBM Plex Mono 400/500 | OFL | `plexmono-latin-{400,500}.woff2`, `font-display: swap` |

Each face has a metric-matched fallback (`size-adjust`/`ascent-override`/
`descent-override`, generated by `scripts/font_metrics.py`) so the swap is CLS-free.
Latin subsets only — the product's copy is English and identifiers are ASCII; adding
subsets is a deliberate future decision. Manrope chosen over Source Sans 3: tighter
letterfit at the 11–13px sizes this product's tables live at. Inter deliberately
avoided (brief: "the over-used Inter-everywhere default").

## D5 — Tailwind without the CDN

**Chosen: Tailwind v3.4 compiled locally, preflight on, content-scanned from
`app/templates/**/*.html`, output committed at `app/static/vendor/tailwind.css`.**

- v3 matches the Play CDN's engine the templates were written against (v4's preflight
  changes default border colors and would silently re-style every page).
- The class set is frozen at build time: a new utility in a template needs
  `npm run build:css` re-run. Phase 6 verification includes rendering every page and
  checking for unstyled regions.
- Google Fonts and the Tailwind CDN script are removed from both `base.html` and
  `login.html`. No third-party request renders any page.

## D6 — CSRF for fetch()-based interactions

Form posts carry the token in a hidden field; JSON `fetch` calls cannot. Pattern
chosen: token published to the app's own pages in `<meta name="csrf-token">` (the
cookie stays HttpOnly), sent back as `X-CSRF-Token`, verified by
`security.verify_csrf_header` — same HMAC, same cookie comparison, same transport
checks (HTTPS, `sec-fetch-site`, Origin). Live now on `POST /api/pv/code`; the
contract for every Phase 4/5 fragment/interaction endpoint.

## D7 — Trust copy consolidation

One component, `_components.html::notice_synthetic`, two placements (banner, footer).
Wired into `base.html` this phase. The Phase 2 landing page reuses the same macro.
Any page needing the long-form boundary text links to the FAQ/About section rather
than restating it (§13.1: persistent compact indicator + detail on demand).
